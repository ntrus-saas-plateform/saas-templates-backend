# P7.0.4-A — Keycloak Topology Compatibility Matrix

**Assumed base:** Keycloak **26.0.x** with Organizations (`KC_FEATURES: organization`).  
**Live version:** VERIFY per environment (see P7.0.4-F01).

| Mode | Description | Feasibility (declared 26.0) | Prerequisites | Limits / Risks | Class |
|------|-------------|----------------------------|---------------|----------------|-------|
| **A** Dedicated realm per tenant | 1 tenant → 1 realm (+ optional orgs) | **Partial** | Controlled createRealm adapter; today only `scripts/import-keycloak-realm.ts` | Realm sprawl; backup/HA; not on `KeycloakAdminPort` | BUILD + VERIFY live || **B** Shared realm + orgs | N tenants → 1 realm, org per tenant | **High** | Matches current Identity pattern + org APIs | Cross-tenant token/org confusion | EXTEND (product bindings) |
| **C** Multi-establishment | 1 tenant → N KC orgs mapped to BB establishments | **High** if Orgs API stable | BB contract for establishment refs; mapping tables | Org ≠ establishment assumption | BUILD mappings |
| **D** Hybrid | Mix A/B/C by product/profile | **Designable** | Topology mode registry; capability discovery | Certification per mode before prod claim | BUILD |

## Isolation requirements (all modes)

- Explicit issuer / audience / client binding verification at readiness  
- No silent reuse of Edge vertical KC org ids  
- Cross-tenant token acceptance → security incident class  
- Keycloak technical ids never used as business primary keys  

## Certification rule

No mode marked production-supported until Mode-specific tests (create, map, isolate, reconcile, revoke) pass against the **actual** Keycloak build in that environment.

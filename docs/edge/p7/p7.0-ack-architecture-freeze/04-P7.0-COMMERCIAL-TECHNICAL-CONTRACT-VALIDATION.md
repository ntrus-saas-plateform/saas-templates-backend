## 7.1 P5 → P7 authorization

### Current port (E2)

`ProvisioningRequestInput`: subscriptionId, subscriptionNumber, accountId, productId, correlationId, optional payload.  
**Missing vs required contract:** authorization_id, operation, authorization_status/decision, entitlement_snapshot ref, policy version, issued_at/expires_at, revocation, dedicated idempotency_key (correlation partial).

### Classification of Unavailable adapter

| Question | Answer |
|----------|--------|
| Acceptable placeholder? | **Yes** — honest fail (E2/E3) |
| Blocker for P7.1? | **No** — P7.1 replaces it for durable request path |
| Blocker for later execution? | Must remain fail-closed until real provider + auth verify |
| Controlled work item? | P7.1.01–03 (+ P5 emit richer auth payload) |

### Frozen authorization contract (minimum fields)

authorization_id · account_id · product_id · subscription_id · tenant_id? · operation · decision/status · entitlement_snapshot_ref · policy_version · issued_at · expires_at? · correlation_id · idempotency_key · revocation · provenance

Properties: explicit, product-scoped, operation-scoped, versioned, auditable, verifiable, replay-resistant, cross-account/product resistant.

## 7.2 P6 → P5

Financial facts via billing coordination (`subscription.billing_coordination.*.v1`). P7 must **not** consume raw payment events for eligibility. **PASS** at architecture level (E2).

## 7.3 Fail-closed matrix (frozen)

| Situation | Required behavior |
|-----------|-------------------|
| Auth absent / expired / revoked | Reject new provisioning; no activation |
| Wrong product / account / subscription | Reject |
| Already consumed | Idempotent no-op or reject duplicate independent request |
| Duplicate delivery | Single durable request |
| P5 unavailable for verify | Fail-closed for auth-sensitive ops |

**Gate C:** PASS WITH CONDITIONS — contract defined; implementation in P7.1; current port insufficient alone (E2).

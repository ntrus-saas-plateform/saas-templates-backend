# 05 — Durable Workflow Validation (Gate D)

| Document ID | P7.0-ACK-05 | Version | 1.0.0 | Date | 2026-11-10 |

## Findings

| Mechanism | Sufficient as P7 engine? | Evidence |
|-----------|--------------------------|----------|
| JobScheduler + Redis lock | **No** | E2 |
| Identity TenantProvisioningOrchestrator | **No** (wrong BC; no compensation/fencing) | E2 |
| Outbox | Reliability for events, not step leases | E2 |
| Proposed internal durable engine | Architecturally acceptable | E1 ADR-002 |

## Required concepts (accepted as target)

Definition, version, execution, step, attempt, checkpoint, lease, fencing token, retry/backoff, timeout, cancel/pause/resume, human task, compensation, DLQ, reconciliation, audit.

## Failure scenarios — expected behavior (design acceptance)

| Scenario | Expected |
|----------|----------|
| External success then crash before checkpoint | Verify-before-retry; no duplicate create |
| Lease holder crash | Lease expiry; fenced successor |
| Dual workers | Fencing token rejects stale |
| Lost success response | Status poll / reconcile before retry |
| Auth revoked mid-flight | Stop activation; compensate/safe halt per policy |
| Broker/DB outage | Durable state; resume |
| Interrupt at activation | Fail-closed; no ACTIVE without evidence |

## Acceptance rule application

Scheduler/queue ≠ durable engine — **confirmed**.

**This ACK:** Does **not** authorize P7.4 engine **code**. Authorizes P7.1 without provisioning execution. Engine design remains ACCEPTED WITH CONDITIONS (complete step model + crash tests before engine code ACK).

**Gate D:** CONDITIONAL PASS for foundational path; engine implementation gated.

## 4. Admin API surface in code

`KeycloakAdminClient` (`src/shared/keycloak/keycloak-admin.client.ts`):

| Capability | Present |
|------------|---------|
| Create/update/list organizations | Yes |
| Organization members add/list/remove | Yes |
| Users / sessions / MFA / IdPs | Yes |
| **Create / delete realm** on `KeycloakAdminPort` | **No** |
| Realm create in ops script | **Yes** — `scripts/import-keycloak-realm.ts` (`createRealm`) — not product provisioning API |
| Client / protocol mapper provisioning for product tenants | **No** dedicated product APIs |
| Realm-per-tenant automation in Edge/P7 | **Absent** |

Client resolves a **single** admin realm via `KeycloakRealmResolver` — oriented to shared-realm org model (Identity), not multi-realm product topology.

**Mode A implication:** realm creation capability exists as an **import script**, not as a reusable admin port. P7.7 must promote a controlled `createRealm` adapter (least privilege) — do not call the import script from workflows. Evidence confirmed by [BB/infra/workflow explore](fcbf16e8-2bac-4efb-9e37-b0beb095290a).

## 6. Distinctions (confirmed required)

`Tenant ≠ Realm ≠ Organization ≠ Establishment` — none of these are equated in a product-tenant model today because the model does not exist. Identity conflates platform tenant ↔ KC org in shared realm — **must not** be copied blindly into P7 Modes A–D.

# P7.0.15 — Architecture Decision Records

**Date:** 2026-11-10  
**Status legend:** Proposed → Accepted (pending formal review) / Conditional

---

## ADR-P7-001 — Provisioning Architecture

**Status:** Proposed  
**Decision:** Implement Provisioning Control System as Edge modular domain(s) inside `saas-templates-backend`, not a new microservice.  
**Why:** Matches Nest hexagonal, shared outbox/RBAC/DB, lower ops cost.  
**Reject:** Greenfield microservice; rewriting P0–P6.  
**Consequence:** Clear module boundaries; no circular BB dependency.

---

## ADR-P7-002 — Workflow Engine

**Status:** Proposed (see also `03-adr-durable-workflow.md`)  
**Decision:** Internal durable workflow engine (Postgres-backed definitions/instances/steps/leases/fencing/compensation).  
**Why:** No Temporal in stack; JobScheduler insufficient; Identity orchestrator wrong BC.  
**Reject (for reference path):** Temporal; pure Redis queues; HTTP-only chains.  
**Gate:** G4 crash recovery test.

---

## ADR-P7-003 — Product Control Contract

**Status:** Proposed  
**Decision:** Versioned Product Control Contract (discovery, provision, IAM prep, config, entitlements, readiness, activation, lifecycle, errors, idempotency). Edge never executes BB business rules.  
**Why:** No HTTP client exists; `edge_integration_contracts` is metadata only.  
**Consequence:** Contract tests mandatory before claiming BB support; first BB may be mock/reference.

---

## ADR-P7-004 — Keycloak Topology Strategy

**Status:** Proposed (see `04-adr-keycloak-topology.md`)  
**Decision:** Support Modes A–D via explicit topology mode; separate product bindings from Edge vertical / Identity orgs; prefer Mode B for SaaS reference path; Mode A requires createRealm capability build + live verify.  
**Why:** KC 26.0 declares Organizations; admin client has org APIs, not realm create.  
**Condition:** Live version VERIFY (P7.0.4-F01).

---

## ADR-P7-005 — Infrastructure Adapter Architecture

**Status:** Proposed  
**Decision:** Port/adapter interfaces for DB/runtime/secrets/network/DNS/TLS; Postgres SaaS adapter first; no K8s mandate.  
**Why:** Compose + Identity provisioner prove Postgres path; multi-cloud absent.  
**Reject:** Kubernetes as obligatory dependency.

---

## ADR-P7-006 — Tenant Provisioning Data Model

**Status:** Proposed (see `05-adr-tenant-identity-boundaries.md`)  
**Decision:** New Edge product-tenant + provisioning aggregates; do not use Identity `tenants` PK; link P5 subscription + optional 089 coordination row; KC ids as technical refs.  
**Entities (minimum):** ProvisioningAuthorization, ProvisioningRequest, ProductTenant, RuntimeBinding, IdentityTopology*, WorkflowInstance*.

---

## ADR-P7-007 — Event & Reliability Strategy

**Status:** Proposed  
**Decision:** Continue CP outbox/inbox/RabbitMQ; standardize event names to `subscription.provisioning.*.v1` (fix doc drift); idempotency keys per authorization; verify-before-retry on unknown outcomes; reconciliation as separate domain.  
**Why:** Proven in P4–P6; P7 needs stronger fencing at workflow layer.

---

## ADR-P7-008 — On-Premise Connectivity Architecture

**Status:** Proposed / DEFER implementation  
**Decision:** Separate Connectivity Agent (outbound-only) + Edge Agent Registry; design interfaces in early phases; implement P7.14 after SaaS path.  
**Why:** No agent code today; enterprise need real but not blocking G1–G10.

---

## ADR-P7-009 — Tenant Lifecycle & Decommissioning

**Status:** Proposed  
**Decision:** Lifecycle ops (suspend/resume/update/migrate/recover/archive/decommission) are workflowized with P5 authorization + evidence; no silent delete; decommission requires approval + export evidence.  
**Why:** Only Identity suspend/KC disable exists today — wrong BC.

---

## ADR-P7-010 — Activation Authorization Boundary

**Status:** Proposed  
**Decision:** Technical activation requires valid P5 authorization + readiness evidence; P6 financial events never directly activate; exceptions audited.  
**Why:** Core control-plane integrity.

---

## ADR-P7-011 — Observability & Audit

**Status:** Proposed  
**Decision:** Structured logs + correlation + `edge_audit_events` (or P7 evidence tables) + OTEL spans per workflow step; metrics for queue latency, provisioning duration, adapter errors.  
**Why:** Extend existing Edge observability rather than new stack.

---

## ADR-P7-012 — Deployment & Runtime Profiles

**Status:** Proposed  
**Decision:** Profiles (Shared SaaS, Dedicated Data, Dedicated Runtime, Private, On-Prem) declared in Runtime Registry; only certified profiles marked available. Reference path: Shared SaaS + Postgres + Mode B IAM.  
**Why:** Prevent overclaiming unsupported topologies.

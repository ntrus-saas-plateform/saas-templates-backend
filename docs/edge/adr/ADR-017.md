# ADR-017 — API Surface: `/api/v1/edge/**` Only; No Silent ERP Contract Changes

## Status

Accepted (P0-A lock)

## Context

Nest URI versioning serves ERP under `/api/v1/...` (platform, identity, commercial, …). OpenAPI and frontend `types/openapi.d.ts` consume those contracts.

## Problem

Extending existing ERP endpoints with optional Edge fields or overloading `/api/v1/platform/**` would silently break clients and blur authz.

## Options considered

| Option | Summary |
|--------|---------|
| A | Add Edge operations onto `/api/v1/platform/admin/**` |
| B | Version bump entire API to `/api/v2` for Edge |
| C | New prefix `/api/v1/edge/**` only; freeze ERP contracts |

## Decision

**Option C.** All Edge Admin HTTP APIs are introduced under **`/api/v1/edge/**`**. Existing ERP routes remain behaviorally unchanged — no silent field meaning changes, no optional Edge-only auth modes on ERP controllers.

## Rationale

Clear gateway routing, OpenAPI tagging, and guard binding; satisfies constraints 1 and 6.

## Security implications

- Edge controllers register Edge auth guards only.  
- ERP guards continue requiring `tenant_id`.  
- Cross-calling: Edge service code must not invoke ERP use cases with fabricated tenant context.

## Operational implications

Separate OpenAPI tag `edge`; rate limits/quota per prefix possible.

## Data implications

DTOs live under `src/modules/edge/presentation/dto/`.

## Migration implications

None for ERP; additive controllers only.

## Rejected alternatives

- **A:** Overload platform-admin — conflicts with ADR-002.  
- **B:** Global v2 — unnecessary churn for ERP clients.

## Consequences

- Frontend Edge proxy maps 1:1 to `/api/v1/edge/**`.  
- Compatibility tests lock ERP response schemas of critical routes.

## Acceptance criteria

- [ ] No ERP route handler gains Edge-only auth bypass.  
- [ ] Edge swagger paths only under `/api/v1/edge/`.  
- [ ] OpenAPI diff for ERP paths is empty (or additive docs only with approval).

## Mandatory constraints

1, 3, 5, 6.

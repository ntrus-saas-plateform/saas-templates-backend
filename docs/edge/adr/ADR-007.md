# ADR-007 — Opaque Vertical Workspace Session

## Status

Accepted (P0-A lock)

## Context

ERP request context is JWT-derived `tenant_context` (ALS). Browser ERP BFF stores tokens in `edge_bff_session`. Keycloak SSO sessions are IdP-side. Edge needs a **workspace** binding (which vertical + membership) that is neither ERP tenant context nor raw KC SSO.

## Problem

Using KC access token claims alone for “active vertical,” or stuffing vertical into `TenantContextService`, collapses domains and breaks multi-tab safety.

## Options considered

| Option | Summary |
|--------|---------|
| A | Store active vertical only in JWT custom claim |
| B | Reuse `TenantContextService` with `tenantId = verticalId` |
| C | Opaque server-side workspace session, distinct from KC SSO and tenant context |

## Decision

**Option C.** After Edge authentication, Control Plane issues an **opaque workspace session** (server-side record + `okapi_edge_*` cookie). Session references: admin id, vertical id, membership id, auth time, expiry, rotation version.  
**Distinct from:** Keycloak SSO session, ERP `edge_bff_session`, and `tenant_context`.

## Rationale

Enables revoke-on-suspend, rotation on vertical switch (ADR-008/020), and constraint 4 separation.

## Security implications

- Session id high-entropy; store hash at rest if cookie carries raw id.  
- Cookie flags: HttpOnly, Secure (prod), SameSite=Lax (or stricter if feasible).  
- Constraint 2: independent secrets/validation/renewal/logout/revocation.

## Operational implications

Session store in CP (Postgres); optional Redis pointer later — Postgres remains authoritative for revoke.

## Data implications

`edge_workspace_sessions` (or equivalent) in CP 073+.

## Migration implications

New table only; no change to ERP session mechanisms.

## Rejected alternatives

- **A:** Claim-only — hard to revoke mid-TTL without denylist complexity tied to wrong realm.  
- **B:** Overloaded tenant context — forbidden by ADR-001/constraints.

## Consequences

- Middleware establishes `vertical_workspace_context` from opaque session, not from ERP guards.  
- KC token still proves identity; workspace session proves vertical binding.

## Acceptance criteria

- [ ] Dual cookie jar: ERP + Edge sessions coexist.  
- [ ] Revoking workspace session does not clear `edge_bff_session`.  
- [ ] No code path sets `TenantContextService` from Edge workspace middleware.

## Mandatory constraints

1, 2, 4, 5, 6.

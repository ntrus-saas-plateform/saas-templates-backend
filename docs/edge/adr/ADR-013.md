# ADR-013 — Delegation with Bounded Ceiling

## Status

Accepted (P0-A lock)

## Context

ERP supports delegations (`011_delegation_emergency.sql`) where grantor delegates a permission subset to grantee with expiry. Edge operators similarly need temporary help-desk elevation without minting permanent global admins.

## Problem

Unbounded delegation (grantor can delegate permissions they do not hold, or perpetual grants) creates hidden superusers.

## Options considered

| Option | Summary |
|--------|---------|
| A | No delegation in Edge P0 |
| B | Full mirror of ERP delegation without ceiling checks |
| C | Delegation allowed with **bounded ceiling** |

## Decision

**Option C.** Edge delegation:

- Grantor may delegate only permissions ⊆ grantor’s **effective** permissions in that vertical (ceiling).  
- Hard **TTL** max (product-defined; shorter than ERP default if ERP is looser).  
- Scoped to a single vertical membership context.  
- Revocable; appears in Edge audit taxonomy.  
- Cannot delegate break-glass approval rights unless policy explicitly allows (default deny).

## Rationale

Reuses ERP pattern safely (constraint 6) with stricter ceiling for platform-ops risk.

## Security implications

- Server recomputes ceiling at grant and at use time.  
- Constraint 5: FE-proposed permission lists filtered server-side.  
- Step-up required to create delegation (ADR-012).

## Operational implications

List active Edge delegations in console; alert on max TTL grants.

## Data implications

`edge_delegations` table (CP 073+), not reuse of `delegations` rows.

## Migration implications

Separate migration; ERP `delegations` untouched (constraint 1).

## Rejected alternatives

- **A:** Blocks legitimate ops workflows.  
- **B:** Unbounded — unacceptable for Edge.

## Consequences

- Authz resolver (ADR-006) includes active Edge delegations.  
- Cache invalidation on grant/revoke (ADR-019).

## Acceptance criteria

- [ ] Grant above ceiling rejected.  
- [ ] Expired delegation ignored.  
- [ ] ERP delegation APIs unchanged.

## Mandatory constraints

1, 5, 6.

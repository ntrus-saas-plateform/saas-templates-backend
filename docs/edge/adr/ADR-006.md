# ADR-006 — Authorization Model (Global + Vertical Roles)

## Status

Accepted (P0-A lock)

## Context

ERP resolves effective permissions from org memberships, roles, delegations, emergency grants, and JWT claims via `AuthorizationService` bound to `TenantContextService`. Edge needs a parallel model without that coupling.

## Problem

If Edge trusts frontend vertical IDs or JWT role names alone, operators can escalate across verticals.

## Options considered

| Option | Summary |
|--------|---------|
| A | JWT roles only |
| B | Copy ERP `AuthorizationService` onto shared `TenantContext` |
| C | Global Edge roles + per-vertical roles/fine-grained permissions; backend authoritative |

## Decision

**Option C.**

- **Global roles** — platform-wide Edge capabilities (e.g. manage verticals catalog, break-glass approve).  
- **Vertical roles + fine-grained permissions** — scoped by membership (ADR-005).  
- **Backend authority** — FE sends selected `verticalId` as hint; server loads membership, binds workspace session, evaluates permissions. Deny by default.

## Rationale

Matches constraint 5 and ERP lessons (DB-backed perms) without merging ALS contexts (constraint 4).

## Security implications

- Edge guards must not call ERP `AuthorizationService` with empty/fake `tenantId`.  
- Permission keys namespaced (`edge:…`) to avoid string collision in logs/metrics.  
- Step-up may wrap sensitive permissions (ADR-012).

## Operational implications

Permission catalog seeded in CP migrations; documented in Edge OpenAPI later.

## Data implications

Role/permission catalog tables for Edge (or namespaced rows clearly separated from ERP `roles`/`permissions` — prefer **separate Edge tables** to satisfy constraint 6).

## Migration implications

Seed in 073+; do not INSERT Edge perms into ERP catalog used by tenant staff.

## Rejected alternatives

- **A:** JWT-only — forgeable / stale.  
- **B:** Shared tenant context — violates constraints 1 and 4.

## Consequences

- Redis may cache decisions (ADR-019) but CP remains SoT.  
- API errors: 401 unauthenticated, 403 authenticated-but-denied, 409 stale workspace (ADR-020).

## Acceptance criteria

- [ ] Deny-by-default tests.  
- [ ] Vertical selector without membership → 403.  
- [ ] ERP permission resolution paths unchanged in regression pack.

## Mandatory constraints

1, 4, 5, 6 (and 2–3 on token path).

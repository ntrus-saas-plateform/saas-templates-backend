# ADR-002 — IAM Isolation: `edge-admin` Realm vs `platform` Realm

## Status

Accepted (P0-A lock) — Decision **2A**

## Context

ERP uses a single Keycloak realm `platform` (`docker/keycloak/platform-realm.json`) with Organizations enabled and JWT `tenant_id` isolation (`KeycloakRealmResolver`). Platform operators today use `platform-admin` role/client for tenant provisioning.

## Problem

Hosting Edge Admin identities in the same realm (or reusing `platform-admin`) would couple SSO sessions, audiences, MFA policies, and org semantics to ERP — breaking isolation and inviting privilege bleed.

## Options considered

| Option | Summary |
|--------|---------|
| A | Same `platform` realm; new roles/clients only |
| B | Repurpose `platform-admin` as Edge operator |
| **2A** | Dedicated realm `edge-admin` |

## Decision

**2A:** Dedicated Keycloak realm **`edge-admin`**, fully separate from **`platform`**. Do **not** repurpose `platform-admin`.

## Rationale

Realm separation is the strongest practical boundary for issuer, password/MFA policy, Organizations meaning, and session cookies at the IdP. Matches locked decision 2A and constraints 1–3.

## Security implications

- Distinct `iss` / JWKS; ERP guards keep current issuer/audience checks.  
- Edge compromise of realm config does not rewrite ERP clients.  
- Constraint 3: audiences/redirects/scopes must not confuse ERP vs Edge.

## Operational implications

- Dual realm import in docker/K8s; dual admin credentials.  
- Backup/restore and key rotation runbooks per realm.  
- Monitoring: separate realm health checks.

## Data implications

Edge user `sub` values live in `edge-admin`; ERP `application_users.identity_id` remain `platform` subjects. No shared user PK assumption.

## Migration implications

No migration of existing `platform-admin` users into Edge automatically. Bootstrap Edge admins via Edge invitations (ADR-011) or controlled realm import.

## Rejected alternatives

- **A:** Shared realm — org semantics conflict (ERP business org vs Edge vertical).  
- **B:** Repurpose platform-admin — explicit non-goal; conflates tenant break-glass with vertical ops.

## Consequences

- New env vars for Edge issuer/JWKS/audience (names must not overwrite ERP).  
- ADR-003 defines clients inside `edge-admin`.

## Acceptance criteria

- [ ] `edge-admin` realm export exists beside `platform-realm.json`.  
- [ ] ERP login path still uses `platform` only.  
- [ ] Automated test: ERP token `iss` rejected by Edge validator and inverse.

## Mandatory constraints

1–6 apply; especially 1 (no ERP regression) and 3 (Keycloak client/realm separation).

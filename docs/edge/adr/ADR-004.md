# ADR-004 — Edge Admin Lifecycle States

## Status

Accepted (P0-A lock)

## Context

ERP `ApplicationUserStatus` (`INVITED`, `PENDING_ACTIVATION`, `ACTIVE`, `SUSPENDED`, `LOCKED`, `DISABLED`, `DELETED`) models tenant staff. Edge operators need an admin lifecycle that covers invitation and deactivation workflows without sharing that enum/table.

## Problem

Reusing ERP user status enums or tables would mix domains and force Edge through tenant-scoped user APIs.

## Options considered

| Option | Summary |
|--------|---------|
| A | Reuse `application_users` + ERP statuses |
| B | Subset of ERP statuses only (`ACTIVE`/`SUSPENDED`) |
| C | Edge-specific state machine |

## Decision

**Option C.** Edge admin lifecycle states:

| State | Meaning |
|-------|---------|
| `INVITED` | Admin record created; invite not yet outstanding/accepted as pending flow requires |
| `INVITATION_PENDING` | Open hashed invitation awaiting accept |
| `ACTIVE` | May authenticate and hold workspace memberships |
| `SUSPENDED` | Blocked; sessions revoked (ADR-008) |
| `DEACTIVATION_PENDING` | Grace / review before terminal deactivation |
| `DEACTIVATED` | Terminal; no login; memberships inert |

Transitions are enforced in Edge domain services (not Keycloak alone).

## Rationale

Matches product language for Edge ops; avoids false equivalence with ERP `PENDING_ACTIVATION` / `DISABLED` / `DELETED`.

## Security implications

- `SUSPENDED` / `DEACTIVATED` must fail authz and revoke workspace sessions.  
- Invitations only meaningful in `INVITED` / `INVITATION_PENDING`.  
- Constraint 1: ERP user lifecycle APIs unchanged.

## Operational implications

Admin support tools need Edge-specific status filters; do not show Edge admins in ERP user lists.

## Data implications

Status column on Edge admin table (CP 073+). Audit events on every transition (ADR-015).

## Migration implications

Greenfield enum in Edge migrations; no ALTER of `application_users`.

## Rejected alternatives

- **A:** Shared table — violates constraint 6.  
- **B:** Too coarse for invitation/deactivation ops.

## Consequences

- UI and APIs expose these six states only.  
- Mapping from KC `enabled=false` → suspend/deactivate is explicit reconcile policy (ADR-010), not silent.

## Acceptance criteria

- [ ] Domain tests cover allowed/denied transitions.  
- [ ] Suspend path revokes sessions.  
- [ ] ERP `ApplicationUserStatus` untouched.

## Mandatory constraints

1, 2, 5, 6 (and 3–4 for related auth paths).

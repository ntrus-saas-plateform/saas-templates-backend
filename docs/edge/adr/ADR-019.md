# ADR-019 — Redis Authz Cache Never Source of Truth

## Status

Accepted (P0-A lock)

## Context

ERP `AuthorizationService` resolves permissions from Postgres per request. Redis exists via `CacheService` (`src/shared/database/cache.service.ts`) for general caching, locks, and token denylist — not as ERP authz SoT today.

## Problem

Caching Edge authz in Redis without strict invalidation would serve stale allow decisions after suspend/revoke/role change.

## Options considered

| Option | Summary |
|--------|---------|
| A | No cache (always DB) |
| B | Redis as authoritative authz store |
| C | Optional Redis cache; **never SoT**; explicit invalidation |

## Decision

**Option C.** Edge may cache effective permission sets / membership snapshots in Redis for latency, but:

- **Source of truth** remains Control Plane Postgres.  
- **Explicit invalidation** on: membership change, role change, suspend/deactivate, delegation/break-glass grant|revoke, workspace session rotate/revoke, config activation affecting authz.  
- Cache miss → load from DB.  
- Negative cache TTLs short; positive TTL capped.  
- On Redis failure → fall back to DB (fail open for availability only on read path, never invent grants).

## Rationale

Performance without weakening revoke semantics (ADR-008); adapted infra reuse (constraint 6).

## Security implications

- Invalidation bugs are security bugs — test them.  
- Cache keys must include admin id, vertical id, rotation/version stamp.  
- Constraint 5: never trust FE to bust cache as security control.

## Operational implications

Metrics for hit/miss/invalidation; admin command to flush Edge authz namespace.

## Data implications

No SoT in Redis; optional key namespace `edge:authz:…`.

## Migration implications

None required; config flags for enable/TTL.

## Rejected alternatives

- **B:** Redis SoT — revoke hazard.  
- **A:** Allowed as default until scale requires C; C remains the architectural rule when caching is on.

## Consequences

- Wire invalidation into Edge use cases (not only TTL).  
- ERP authz path need not adopt Redis for P0.

## Acceptance criteria

- [ ] After suspend, cached allow cannot succeed beyond invalidation (test with cache forced on).  
- [ ] Redis down → Edge authz still correct from DB.  
- [ ] ERP authorization behavior unchanged.

## Mandatory constraints

1, 2, 5, 6.

# ADR-005 — Membership: One per (Admin, Vertical)

## Status

Accepted (P0-A lock)

## Context

ERP allows multiple org memberships per user within a tenant (`user_organization_memberships`). Edge admins operate across vertical workspaces with independent permissions.

## Problem

Ambiguous cardinality or shared permission blobs across verticals would cause over-privilege and unsafe UI defaults.

## Options considered

| Option | Summary |
|--------|---------|
| A | Global permission set only (no per-vertical membership) |
| B | Many memberships per vertical (duplicates) |
| C | At most one membership per `(admin_id, vertical_id)`; independent perms per workspace |

## Decision

**Option C.** Exactly **one** membership row per `(edge_admin, vertical)`. Permissions/roles on that membership are **independent** per workspace. An admin may hold many memberships (different verticals).

## Rationale

Simplifies authz resolution and workspace switch (ADR-007/020). Aligns with “one KC org = one vertical” (ADR-003).

## Security implications

- Switching vertical never inherits previous vertical’s permission set.  
- Constraint 5: listing verticals from FE is not proof of membership.  
- Unique DB constraint prevents duplicate grants.

## Operational implications

Support must diagnose “which vertical membership” when access fails.

## Data implications

`edge_vertical_memberships` (name TBD) with `UNIQUE(admin_id, vertical_id)`, status, roles/permissions JSON or junction tables.

## Migration implications

CP 073+; no use of `user_organization_memberships`.

## Rejected alternatives

- **A:** Global-only — cannot isolate vertical blast radius.  
- **B:** Duplicate memberships — nondeterministic authz.

## Consequences

- Workspace session binds a single membership (ADR-007).  
- Delegation ceiling evaluated within that membership (ADR-013).

## Acceptance criteria

- [ ] Unique constraint enforced in migration.  
- [ ] Authz tests: perms in vertical A do not apply in B.  
- [ ] ERP membership tables unchanged.

## Mandatory constraints

1, 4, 5, 6.

# ADR-010 — Idempotent Reconcile; Never Auto-Grant on Drift

## Status

Accepted (P0-A lock)

## Context

ERP `ReconcileKeycloakUseCase` detects drift between Keycloak and app DB and records `reconciliation_reports`. Repairs are controlled — privilege inventing from drift is dangerous.

## Problem

Auto-creating Edge memberships or elevating roles when KC and CP disagree could grant vertical admin on misconfiguration.

## Options considered

| Option | Summary |
|--------|---------|
| A | Auto-grant memberships to match KC org members |
| B | Auto-disable only; ignore grants |
| C | Idempotent reconcile; report drift; **never auto-grant** on drift |

## Decision

**Option C.** Edge reconcile is **idempotent** and safe to re-run. It may:

- Update non-authoritative mirrors (e.g. display names, KC org id sync flags).  
- Emit drift records (missing mapping, unexpected KC member, enabled mismatch).  

It must **never** auto-grant vertical memberships, global roles, or permissions because drift was observed. Grants occur only via explicit admin actions / accepted invitations / approved workflows.

## Rationale

Fail-closed privilege model; mirrors ERP caution while being stricter on grants (constraint 5).

## Security implications

- Drift of type “KC member without CP membership” → alert, not grant.  
- Drift “CP membership without KC” → mark stale / suspend path per policy, still no new grants.

## Operational implications

Dashboards for Edge reconciliation reports; on-call playbook to resolve manually.

## Data implications

Reuse pattern of `reconciliation_reports` or Edge-specific report table — prefer Edge-named table to avoid mixing ERP tenant reports (constraint 6).

## Migration implications

Report table in 073+ if not reusing ERP table with a discriminator (discriminator on ERP table is discouraged).

## Rejected alternatives

- **A:** Auto-grant — unacceptable privilege risk.  
- **B:** Disable-only without reporting — operability failure.

## Consequences

- Product must ship invite/approve UX; reconcile is not an onboarding shortcut.  
- Tests assert zero membership inserts inside reconcile grant paths.

## Acceptance criteria

- [ ] Re-run reconcile twice → same drift set (idempotent).  
- [ ] Fixture with KC-only member → report, membership count unchanged.  
- [ ] ERP reconcile behavior unchanged.

## Mandatory constraints

1, 5, 6.

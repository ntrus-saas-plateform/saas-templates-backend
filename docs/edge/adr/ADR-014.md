# ADR-014 — Break-Glass: Temporary, Never Permanent

## Status

Accepted (P0-A lock)

## Context

ERP emergency access grants are time-bounded (`emergency_access_grants` with `expires_at`, `revoked_at`). Edge Admin needs break-glass for vertical outages / locked admins without creating standing god-mode accounts.

## Problem

Permanent break-glass accounts or open-ended Edge roles become unauditably powerful and bypass MFA policy discipline.

## Options considered

| Option | Summary |
|--------|---------|
| A | Standing `edge-superadmin` without expiry |
| B | Reuse ERP `emergency_access_grants` with null tenant |
| C | Temporary Edge break-glass only; never permanent |

## Decision

**Option C.** Break-glass in Edge is **always temporary**:

- Explicit reason, approver, scope, **mandatory expires_at**.  
- No UI/API path to create non-expiring grants.  
- Auto-expire job + revoke workspace sessions when grant ends.  
- Step-up + dual control (requester ≠ approver) by default.  
- Full audit trail (ADR-015).

## Rationale

Aligns with ERP emergency design but forbids permanence explicitly for Edge threat model.

## Security implications

- Scope cannot include “all verticals forever.”  
- Constraint 2: ending break-glass revokes Edge sessions, not ERP.  
- Constraint 5: scope evaluated server-side.

## Operational implications

Paging/runbook for approval; post-incident review required.

## Data implications

`edge_emergency_grants` (CP 073+); separate from ERP table (constraint 6).

## Migration implications

CHECK constraint `expires_at > created_at` and application max TTL.

## Rejected alternatives

- **A:** Permanent superadmin — rejected.  
- **B:** Shared ERP table — domain mix / null tenant hacks.

## Consequences

- Product copy must say “temporary access.”  
- Reconcile never creates break-glass (ADR-010).

## Acceptance criteria

- [ ] API rejects missing/too-long TTL.  
- [ ] Expired grant denied in authz.  
- [ ] ERP emergency endpoints unchanged.

## Mandatory constraints

1, 2, 5, 6.
